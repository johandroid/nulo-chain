# Noir ZKP on pallet-revive

This example proves private token-balance comparisons with Noir, generates a Barretenberg Solidity verifier, uploads the verifier to `pallet-revive`, deploys a small wrapper contract, and submits two valid proofs to the wrapper:

- one account has more tokens than another account, without revealing either balance
- one account has more tokens than a public threshold, without revealing the account balance

The runtime already has `pallet-revive` enabled with EVM bytecode allowed. The example does not change runtime code.

The companion browser tester is the root-level `../../web/` project. This directory intentionally contains only the Noir circuit, Solidity wrapper, build/deploy scripts, and tests needed to produce and submit the generated artifacts.

## Prerequisites

- `node` and `npm`
- `solc`
- Noir `nargo`
- Barretenberg `bb`
- A local Nulo dev node at `ws://127.0.0.1:9944`

Start the chain from the repository root:

```sh
polkadot-omni-node --chain ./chain_spec.json --dev --dev-block-time 1000 --rpc-port 9944
```

## Build And Deploy

From this directory:

```sh
npm install
npm run build
REVIVE_REF_TIME=500000000000 npm run deploy
```

The deploy script defaults to Alice:

```text
SURI=//Alice
WS=ws://127.0.0.1:9944
```

Override them when needed:

```sh
WS=ws://127.0.0.1:9944 SURI=//Bob npm run deploy
```

If your local node is running on a non-default websocket port, pass it with `WS`, for example:

```sh
REVIVE_REF_TIME=500000000000 WS=ws://127.0.0.1:39944 npm run deploy
```

## What Gets Built

- `src/main.nr`: Noir circuit with two public proof modes and private balances/salts.
- `Prover.dominance.toml`: demo witness proving `account_balance > other_balance`.
- `Prover.threshold.toml`: demo witness proving `account_balance > threshold`.
- `target/Verifier.sol`: generated by `bb write_solidity_verifier`.
- `contracts/BalanceProofGate.sol`: wrapper that calls the generated verifier and emits comparison events.
- `target/build.json`: compiled ABI and EVM creation bytecode.
- `target/proofs/dominance/*`: proof and public inputs for hidden-balance-vs-hidden-balance comparison.
- `target/proofs/threshold/*`: proof and public inputs for hidden-balance-vs-public-threshold comparison.

The circuit returns Pedersen commitments to the private balances as public outputs. The raw balances and salts remain private witness values.

`pallet-revive` EVM constructors expect constructor arguments to be appended to creation bytecode. The script does that for `BalanceProofGate` and passes empty Revive constructor `data`.

The Barretenberg Solidity verifier may contain Solidity library links. The deploy script uploads those libraries first, links their deployed Revive addresses into the verifier bytecode, then uploads the linked verifier.

## Failure Check

Run with a tampered threshold public input:

```sh
npm run deploy:invalid
```

This should fail during `revive.call` because the threshold proof does not match the modified public input.

## Useful Environment Variables

- `WS`: websocket endpoint, default `ws://127.0.0.1:9944`
- `SURI`: Substrate dev secret URI, default `//Alice`
- `REVIVE_REF_TIME`: call/deploy weight ref time, default `1900000000000`; use `500000000000` on the current local node if the larger default exceeds block limits
- `REVIVE_PROOF_SIZE`: call/deploy weight proof size, default `3000000`
- `REVIVE_STORAGE_DEPOSIT`: storage deposit limit, default `100000000000000000`

## Browser Tester

After `npm run build`, sync the generated files into the root web app:

```sh
cd ../../web
npm install
npm run sync:artifacts
npm run dev
```

The sync step copies `target/build.json` and `target/proofs/*` into `web/public/artifacts/`. Those copied files are ignored and can be regenerated at any time.
